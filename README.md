# BSGC Workspace

업체별 처리 절차, 진행 중 업무와 기한, 완료 기록과 특이 처리 사례를 한곳에서 관리하는 회사 내부용 업무 공간입니다. 첨부 로고와 로고 심볼 파비콘이 들어가 있습니다.

화면(`index.html`)은 GitHub Pages에서 열고, 업무 데이터(`data.enc.json`)는 회사 Google Drive의 유틸 폴더에 보관합니다.

| 파일 | 위치 | 용도 |
|---|---|---|
| `index.html` | GitHub 저장소 | 화면 뼈대. 아래 `css/`, `js/` 파일을 불러옵니다 |
| `css/app.css` | GitHub 저장소 | 화면 디자인 |
| `js/*.js` (9개) | GitHub 저장소 | 기능별 코드: core(설정·암호화·로그인), sync(Drive 자동 저장), views(화면·업체 인식), collect(자동 수집), tools(KC·연락처·수수료·B/L), accounts-mail(계정·메일 초안), dialogs(입력 창), import(사업자등록증·병합), events(버튼 연결) |
| `logo.png`, `logo-dark.png`, `favicon.png`, `apple-touch-icon.png` | GitHub 저장소 | 로고와 아이콘. `index.html`과 같은 위치에 올립니다. |
| `README.md` | GitHub 저장소 | 이 안내문 |
| `data.enc.json` | Google Drive 유틸 폴더 | 암호화된 업무 데이터. **GitHub에는 올리지 않습니다.** |
| `gmail-to-ledger.gs` | Google Apps Script | Drive 자동 저장, customs@ 메일 색인, 자동 수집, B/L 조회 (이름은 예전 그대로). 저장소에 둘 필요 없습니다. |
| `collector/` 폴더 | 사무실 상시 PC | 한비로 customs@ 메일 수집기. **GitHub에 올리지 않습니다.** |

## 보안 구조

- GitHub 저장소에는 데이터가 없는 화면 코드만 있습니다. 저장소가 공개되어 있어도 업무 내용은 드러나지 않습니다.
- 업무 데이터는 브라우저 안에서 비밀번호로 암호화(AES-256-GCM)된 뒤 파일로 저장됩니다. 비밀번호는 어디에도 저장되지 않습니다.
- 비밀번호는 단어 네다섯 개를 이어 붙인 16자 이상으로 정하세요. 잊으면 복구할 수 없습니다.
- 주민등록번호, 계좌번호, 개인 연락처 같은 개인정보는 기록에 넣지 마세요. 원본 서류는 Drive에 두고 링크만 남기세요.
- Apps Script 연동 주소와 토큰도 암호화된 데이터 안에 저장됩니다.

## 처음 설치

1. GitHub 저장소(`bluestripe_workspace`)에 `index.html`, `README.md`, 로고·아이콘, 그리고 `css`, `js` **폴더째** 올립니다 (Add file → Upload files에 폴더를 끌어다 놓기 → Commit changes). `drive-import-*.json` 같은 평문 자료는 올리지 마세요.
   - 코드를 고친 뒤에는 `index.html`의 `?v=` 뒤 값을 바꿔 올리면 직원 브라우저가 새 파일을 받습니다.
2. Settings → Pages에서 Source를 "Deploy from a branch", Branch를 `main` / `(root)`로 두고 Save. 1~2분 뒤 `https://<아이디>.github.io/bluestripe_workspace/` 로 열립니다.
3. 사이트에 접속해 비밀번호를 정하고 "새 대장 만들기"를 누릅니다.
4. "Drive 자동 저장"을 켭니다(아래). 켜지 않을 때는 오른쪽 위 "암호화 파일 받기"로 받은 `data.enc.json`을 Drive 유틸 폴더에 저장합니다.

**권장 설정 두 가지**

- **PC용 Google Drive 설치.** 유틸 폴더가 탐색기의 일반 폴더처럼 보여서, 저장하고 여는 일이 로컬 파일처럼 간단해집니다.
- **크롬 다운로드 위치 확인 켜기.** 크롬 설정 → 다운로드 → "다운로드 전에 각 파일의 저장 위치 확인"을 켜면, 파일을 받을 때마다 유틸 폴더를 골라 바로 덮어쓸 수 있습니다.

## Drive 자동 저장 (권장)

Apps Script 웹 앱(아래 "customs@ 메일 수집"과 같은 것)을 연결하면, 입력할 때마다 몇 초 뒤 Drive의 `data.enc.json`에 자동으로 저장됩니다. "암호화 파일 받기 → 덮어쓰기"를 손으로 할 필요가 없습니다.

- **암호화는 그대로입니다.** 브라우저에서 암호화한 파일만 Apps Script로 보내므로, 스크립트도 Google도 내용을 볼 수 없습니다.
- **여러 명이 동시에 써도 됩니다.** 파일에 저장 번호가 있어서, 그사이 다른 계정이 저장했으면 내 변경과 그 사람의 변경을 업체·기록·절차 단위로 합친 뒤 저장합니다. 같은 기록의 다른 칸을 고쳤으면 둘 다 남고, 같은 칸을 둘 다 고쳤으면 나중에 저장한 사람 것이 남습니다. 한쪽이 지운 기록을 다른 쪽이 고쳤으면 지우지 않고 남깁니다.
- **다른 계정의 저장은 90초마다 확인**해서 화면에 반영합니다. 오른쪽 위에 "Drive 저장됨 11/6 14:32 · 김주임"처럼 마지막 저장 시각과 저장한 사람이 보입니다.
- **인터넷이 끊기면** "서버 연결 안 됨 (이 PC에 보관 중)"으로 바뀌고, 입력한 내용은 이 PC 브라우저에 암호화되어 남아 있다가 연결되면 저장됩니다. 저장 전에 창을 닫으려 하면 경고가 뜹니다.
- **날짜별 사본**: 하루 한 번, 그날 처음 저장하기 직전 상태를 `data.enc.json`과 같은 폴더의 `data-snapshots`에 `data.enc.2026-11-06.json`처럼 남깁니다. 최근 30개를 보관합니다(`SNAP_KEEP`). 되돌릴 때는 그 파일을 "다른 대장 파일 열기"로 열면 됩니다.
- "파일 백업" 버튼(예전 "암호화 파일 받기")은 그대로 쓸 수 있습니다.

**켜는 방법 (관리자, 한 번)**

1. `gmail-to-ledger.gs` 위쪽의 `DATA_FOLDER_ID`에 Drive 유틸 폴더 ID를 넣습니다. 폴더 주소 `drive.google.com/drive/folders/` 뒤의 문자열입니다. 비워 두면 내 드라이브에서 `data.enc.json`을 찾습니다.
2. 스크립트를 덮어쓰고 배포 → 배포 관리 → 수정 → **새 버전**으로 다시 배포합니다.
3. Workspace "데이터" → "Apps Script 연동"에 웹 앱 주소와 토큰을 넣고 저장합니다. 곧바로 Drive 파일과 합쳐 저장하고, 상단에 "Drive 저장됨"이 보이면 끝입니다.

**직원 PC에서 처음 열 때**: 로그인 화면 아래 "서버 주소로 연결"에 웹 앱 주소와 토큰을 넣으면 Drive의 Workspace를 받아 옵니다. 그다음부터는 사이트를 열면 최신 파일을 먼저 받아 오므로 아이디와 비밀번호만 넣으면 됩니다. Drive PC 앱이 없어도 됩니다.

알아 둘 점:

- 다음 로그인 때 최신 파일을 먼저 받기 위해 웹 앱 주소와 토큰이 그 PC 브라우저에 남습니다. 공용 PC에서는 쓰지 마세요.
- 입력 창이 열려 있는 동안에는 다른 계정의 변경을 반영하지 않고, 창을 닫은 뒤 반영합니다.
- Apps Script가 한 번에 저장하는 파일은 10MB까지입니다. 지금 크기라면 한참 여유가 있습니다.

## 자동 저장 없이 쓸 때

Apps Script를 연결하지 않으면 예전처럼 씁니다.

1. 하루를 마칠 때 상단에 "Drive에 저장할 변경이 있습니다"가 보이면 "암호화 파일 받기" → 유틸 폴더의 `data.enc.json`에 덮어씁니다.
2. 다른 PC에서는 "Drive에서 대장 파일 열기" 또는 "다른 대장 파일 열기"로 Drive 파일을 고르고 비밀번호를 넣습니다. 브라우저에 남은 내용과 Drive 파일 중 더 최근 것이 열립니다.
3. 이 방식에서는 **두 PC에서 동시에 입력하지 마세요.** 나중에 덮어쓴 파일만 남습니다. 파일 이름은 늘 `data.enc.json`으로 유지하세요.

## 로그인과 계정

계정마다 아이디와 비밀번호로 로그인합니다. 데이터는 하나의 무작위 키로 암호화되고, 계정마다 자기 비밀번호로 그 키를 감싸 두는 방식이라 모든 계정이 같은 Workspace를 엽니다.

- **예전 비밀번호 방식에서 넘어올 때**: 로그인 화면에서 아이디를 비우고 예전 비밀번호만 넣으면, 관리자 계정 `admin`으로 바뀝니다. 바뀐 뒤 "암호화 파일 받기"로 Drive 파일을 새로 저장하세요.
- **직원 계정 추가**: 관리자로 로그인 → 왼쪽 "계정 관리" → "계정 추가". 처음 비밀번호는 본인에게 따로 전하고, 첫 로그인 뒤 "데이터" → "내 비밀번호 변경"에서 바꾸게 하세요.
- **계정을 바꾸면** 자동 저장으로 다른 PC에 반영됩니다(자동 저장을 쓰지 않으면 암호화 파일을 새로 받아 Drive에 저장하세요).
- **한계**: 서버 없이 브라우저에서 동작하므로, 계정을 지워도 그 전에 받아 둔 파일은 그 계정 비밀번호로 열립니다. 퇴사자 계정을 지울 때는 Drive 공유 권한과 이전 버전 파일도 함께 정리하세요. 기록에는 작성한 계정이 함께 남습니다.
- **직원이 퇴사하면** Apps Script에서 `resetToken`을 실행해 토큰을 바꾸고, 관리자가 "데이터 → Apps Script 연동"에 새 토큰을 넣으세요. 토큰은 각 PC 브라우저에도 남아 있으므로 바꾸지 않으면 예전 직원 PC에서 계속 연결됩니다. 남은 직원은 다음 로그인 때 첫 화면의 "서버 주소로 연결"에 새 토큰을 한 번 넣으면 됩니다.

## 거래업체 정보

- **사업자등록증 읽기**: 업체 추가·수정 창 맨 위의 "사업자등록증 읽기"에서 홈택스에서 받은 PDF를 고르면 등록번호, 상호, 대표자, 개업일, 사업장 주소, 업태·종목을 채웁니다. 파일은 브라우저 안에서만 처리됩니다. 스캔본이나 사진은 Drive의 BSGC-Backup/사업자등록증 폴더에 올린 뒤 "거래업체 리스트 → 사업자등록증 폴더 반영"으로 읽습니다.
- **메일에서 담당자 스캔**: 업체 화면의 "메일에서 담당자 스캔"을 누르면 Apps Script가 customs@ 메일 색인(최근 1년)에서 그 업체와 주고받은 사람과 최근 업무 메일 제목을 찾아 보여 줍니다. 저장할 담당자를 고르면 업체 화면에 담당자 목록과 최근 업무가 표시됩니다. 업체 정보의 검색어에 메일 도메인(`@abc.co.kr`)을 넣어 두면 그 도메인과 주고받은 메일을, 비워 두면 **제목에 업체명이 들어간 메일만** 찾습니다. 보안을 위해 gmail.com·naver.com 같은 공용 메일 도메인과 우리 회사 도메인(`OWN_DOMAINS`)은 검색할 수 없고, 그 밖의 임의 단어로 메일함을 검색할 수도 없습니다.

## 연락처

왼쪽 "연락처"에 선사, 포워더, 창고, 터미널, 세관, 운송, 택배 연락처를 모았습니다. 구분 버튼으로 거르고, 검색창에 이름·번호·부호·메모로 찾습니다. `drive-import-v3-연락처-수수료.json`을 가져오면 Drive의 "창고,세관,포워더 담당자 연락처"와 "각 선사별 연락처" 내용이 들어갑니다. 원본 파일에 있던 선사·터미널 사이트 아이디와 비밀번호는 옮기지 않았습니다. 계정 정보는 비밀번호 관리 프로그램에 따로 두세요.

## 통관수수료 계산

왼쪽 "수수료 계산"에서 신고금액과 수수료 기준을 고르면 공급가, 부가세, 합계가 바로 나옵니다. 계산 방식은 "통관수수료계산_rev.1"과 같습니다: 수수료 = 신고금액 × 요율(10원 미만 버림), 부가세 = 수수료의 10%(10원 미만 버림). 최소·최대 공급가나 정액이 있는 기준은 그 값을 적용합니다. 검사대행, 개별담보 같은 추가 항목은 "항목 | 금액 | Y(과세)" 형식으로 넣습니다.

가져온 기준: 일반 수입 0.2%, 일반 수출 0.15%, TDF 수출 0.07%(최소 27,000원), 비슈어로지스포딩 0.15%, 케이디인터내셔널·우노테크 0.18%, 피앤피 0.1%, 빠니니코리아 0.15%, 티에스코포레이션(최소 3만·최대 10만원, 요율 확인 필요), 수출 0.12%(업체 확인 필요), 뉴맨코퍼레이션 정액 12,000원. 기준은 화면에서 고치거나 추가할 수 있습니다.

## B/L 조회

상단 검색창에 B/L 번호를 넣으면 그 번호가 든 업무 기록을 찾고(하이픈·공백은 무시), 결과 위의 "UNI-PASS 조회"로 화물진행정보도 바로 볼 수 있습니다. 기록 창에는 B/L 번호 칸이 따로 있습니다. 조회하면 관세청 UNI-PASS 화물통관진행정보(진행상태, 선박, 입항일, 품명, 처리 이력)를 보여 줍니다. 같은 번호의 화물이 여러 건이면 화물관리번호를 골라 다시 조회합니다.

1. UNI-PASS 오픈API에서 "화물통관진행정보조회" 인증키를 발급받습니다.
2. Apps Script의 `saveUnipassKeys` 함수에 서비스별 키(API001 화물통관, API002 수출이행, API049 납부, API052 정정, API003 요건, API004 검사검역, API032 전자첨부)를 넣고 한 번 실행한 뒤 코드에서 키를 지웁니다. 키가 모두 같다면 API001에만 넣어도 됩니다.
3. 스크립트를 고쳤으니 배포 → 배포 관리 → 수정 → 새 버전으로 다시 배포합니다.

UNI-PASS 오픈API는 38010 포트를 씁니다. Apps Script에서 이 포트 연결이 막히면 "UNI-PASS에 연결하지 못했습니다"가 나오는데, 그때는 화면의 "UNI-PASS 열기"로 직접 조회하세요.

## 거래업체 리스트와 사업자등록증 일괄 반영

왼쪽 "거래업체 리스트"에서 회사명, 대표자, 사업장 소재지, 업무담당자, 관련업무를 한 표로 봅니다. "사업자등록증 폴더 반영"을 누르면:

1. Apps Script가 Drive의 BSGC-Backup/사업자등록증 폴더 파일을 Google의 글자 인식으로 읽어 회사명, 대표자, 주소, 등록번호, 개업일, 업태·종목만 돌려줍니다. 원문은 보내지 않습니다. 한 번 읽은 파일은 기억해 두었다가 다시 읽지 않고, 파일이 바뀐 경우에만 다시 읽습니다.
2. 결과 표에서 반영할 업체를 고릅니다. 등록번호나 상호가 같은 기존 업체는 합쳐집니다.
3. "메일에서 업무담당자와 관련업무도 찾기"를 켜 두면 업체마다 최근 1년 메일에서 2통 이상 주고받은 담당자와 최근 업무 메일을 붙입니다.

처음 한 번 준비할 것: Apps Script 편집기 왼쪽 "서비스(+)"에서 **Drive API**를 추가하고, 스크립트를 새 버전으로 다시 배포합니다. 파일이 많으면 15개씩 나눠 자동으로 이어서 읽습니다. 처음부터 다시 읽으려면 Apps Script에서 `resetBizCache`를 실행합니다.

## 자동 수집 (매일 08시, 매주 월요일 15시)

수출입통관 업무를 마치고 BSGC-Backup의 **수입**, **수출** 폴더에 자료를 올리면, 매일 아침 8시에 Apps Script가 새로 올라온 파일을 확인합니다.

- 파일명에서 B/L 번호와 신고번호를 찾고, 그 번호로 최근 120일 customs@ 메일 색인을 찾아 관련 메일(제목, 날짜, 앞부분)을 붙입니다.
- 파일명이나 폴더명에 정정, 사유서, 보완, 기각, 반송, 재수출, 재수입, 사후, 경정, 수정신고, 검사, 불합격, 담보, 외환, 과오납, 환급, 취하, 폐기, 멸각이 들어 있으면 특이 절차로 표시합니다.
- Workspace에 로그인하면 결과를 받아 와서, 파일명·폴더명에서 업체를 알아본 자료는 그 업체의 완료 기록으로 자동으로 넣습니다. 업체는 ① 담당자 메일 주소·메일 도메인 검색어 ② 검색어(약칭) ③ 업체명 순으로 찾습니다. 두 글자 이하 한글 이름이나 영문 이름은 앞뒤가 다른 글자와 붙어 있으면 인정하지 않으므로, '레이'는 '레이_정정.pdf'에는 걸리지만 '디스플레이', '레이저'에는 걸리지 않습니다. 길이가 같은 두 업체가 함께 걸리면 추측하지 않고 미분류로 남깁니다. 같은 B/L·신고번호 기록이 이미 있으면 자료 링크만 덧붙입니다.
- 업체를 알아보지 못한 자료는 왼쪽 "자동 수집"에 남습니다. 업체를 골라 반영하거나 무시합니다. "지금 확인"으로 바로 실행할 수도 있습니다.
- 데이터는 암호화되어 있어 Apps Script가 Workspace 파일을 직접 고칠 수는 없습니다. 그래서 수집 결과는 내 드라이브의 `bsgc-workspace-inbox.json`에 모아 두고, 로그인할 때 반영합니다. 반영 후에는 평소처럼 암호화 파일을 받아 Drive에 저장하세요.
- 특이 절차 내용(무엇이 달랐는지)은 파일명과 메일만으로는 알 수 없으므로, 자동 기록의 특이 처리 내용을 확인해 보완해 주세요.

**매주 월요일 15시**에는 BSGC-Backup 전체(수입·수출 제외)에서 지난주 새로 올라온 자료를 확인합니다.

- 업체정보, FTA 등 폴더의 새 자료는 업체별로 묶어 "[폴더명] 자료 갱신" 기록으로 넣습니다. 정산서 폴더는 수집하지 않습니다(`WEEKLY_EXCLUDE`에서 조정).
- "토스템, 베닉스코리아 주간 수입통관진행현황" 폴더에서 파일명 날짜가 가장 최근인 진행현황을 읽어, B/L별 진행 단계, 반입일, 창고, 청구·입금, 특이사항을 토스템·토탈에프앤비 기록에 반영합니다. 같은 B/L 기록이 있으면 최신 현황으로 갱신하고, 출고 완료면 완료로 바꿉니다. 토탈에프앤비 거래처 구분은 `gmail-to-ledger.gs`의 `FNB_PARTNERS`에서 고칩니다.
- "자동 수집" 화면의 "지금 확인"을 누르면 매일·매주 작업을 바로 실행합니다.

준비: `gmail-to-ledger.gs`를 덮어쓰고 새 버전으로 재배포한 뒤 `installTriggers`를 한 번 실행합니다. 예전에 `installDailyTrigger`를 실행했어도 다시 실행하면 두 예약으로 정리됩니다.

## 업체 폴더와 거래 기간

왼쪽 업체 목록은 두 폴더로 나뉩니다.

- **1년 이상 거래 유지**: 거래 기간이 12개월 이상이고 최근 12개월 안에 업무가 있는 업체
- **그 외 업체**: 1년 미만이거나 근거가 부족한 업체, 1년 넘게 업무가 없는 업체

거래 기간은 업체 정보의 "거래 시작(월)", "최근 업무(월)"과 그 업체 기록의 날짜를 합쳐 계산하므로, 기록이 쌓이면 자동으로 폴더가 바뀝니다. 업체 화면 이름 아래에 기간과 판정이 보이고, 마우스를 올리면 근거가 나옵니다.

## Drive 자료 가져오기

"데이터" → "JSON 가져오기"에 병합용 파일(`drive-import-…json`)을 넣으면 지금 대장에 추가됩니다. 같은 이름의 업체는 합쳐지고, 거래 기간은 더 이른 시작·더 늦은 최근 월로 갱신되며, 이미 있는 절차와 기록은 건너뜁니다. 병합용 파일은 평문이니 가져온 뒤 지우거나 개인 폴더에만 두세요.

## 업무 흐름

**새 건을 받으면** 홈의 "업무 시작"을 누르거나, 업체 화면의 절차 카드에서 "이 절차로 시작"을 누릅니다. 절차의 단계와 필요 서류가 체크리스트로 들어갑니다. 입력창 아래에는 그 업체의 같은 업무 이력, 다른 업체의 같은 유형 특이 사례, 고른 품목의 수입요건이 함께 보입니다.

**진행하면서** 기록 카드의 "단계 n/m"을 펼쳐 항목을 체크합니다. 체크한 날짜가 함께 남습니다.

**기한이 생기면** 기록 수정 창의 "기한"에서 종류와 기준일을 넣습니다. 홈의 "챙길 기한"에 날짜순으로 뜨고, 7일 이내는 빨간 테두리, 지난 기한은 빨간 바탕으로 표시됩니다. 처리했으면 체크박스를 눌러 목록에서 뺍니다.

**끝나면** "완료 처리"를 누릅니다. 진행 요약을 비워 두면 체크리스트 진행 내역으로 자동 작성됩니다. 일반 절차와 다르게 처리했다면 "일반 절차와 다르게 처리함"을 체크하고 특이 처리 내용을 적습니다.

**특이 사례가 쌓이면** 카드의 "절차에 반영"으로 다음에 적용할 점을 해당 절차의 주의사항에 덧붙입니다. 날짜와 함께 남아 어느 사례에서 나온 내용인지 알 수 있습니다.

## 케이스 번호·서류·제안 (케이스 중심 기능)

**케이스 번호**: 모든 기록에 `2026-I-001` 같은 번호가 자동으로 붙습니다(연도-구분-일련번호. I 수입·요건·화학물질, E 수출, F FTA, R 환급, C AEO·품목분류·외환, X 기타). 기존 기록도 접수일 순서로 한 번에 붙습니다. 카드의 번호를 누르면 `[2026-I-001]`이 복사되고, **메일 제목에 넣어 보내면 회신이 그 기록에 자동으로 붙습니다.** 검색창에 번호를 넣어도 찾아집니다.

**서류 표시**: 카드에 필요한 서류가 ✓/✗로 보입니다. 기준은 기록의 "필요 서류" 목록(없으면 수입통관 Invoice·Packing List·B/L, 수출신고 Invoice·Packing List)이고, 자동 수집된 Drive 자료와 customs@ 메일 첨부 파일명에서 Invoice, Packing List, B/L, 원산지증명서, 신고필증, 검역·검사, 요건·확인서, 정산서를 알아봅니다. 같은 서류가 여러 번 들어오면 가장 최근 파일 이름이 마우스를 올렸을 때 보입니다. 파일명으로 판단하므로 틀릴 수 있습니다.

**업무 완료 자동 분류**: 진행 중인 기록은 "통관완료 → 정산완료 → 완료" 순서로 자동 판정합니다.
- **통관완료**: 수입은 UNI-PASS 화물통관 진행정보(B/L)에서 수입신고수리를 확인하고, 세금 납부(API049) 또는 반출신고까지 확인되면 표시합니다. 신고번호가 비어 있으면 UNI-PASS 값으로 채웁니다. 수출은 수출이행 내역(API002, 신고번호 또는 B/L)에서 선적완료가 확인되면 표시하고, 적재의무기한을 기한 목록에 자동으로 넣습니다. 로그인할 때 진행 중 건을 12시간에 한 번, 15건씩 확인합니다.
- **정산완료**: 기록에 붙은 customs@ 메일 제목에 "정산서"가 있으면 표시합니다. 업체 정보의 정산 방식을 "월 정산"으로 해 두면 통관완료만으로 완료됩니다.
- 둘 다 확인되면 **자동으로 완료**하고 카드에 "자동 완료"와 근거를 남깁니다. 홈의 "최근 7일 자동 완료"에서 확인하고 "되돌리기"를 누르면 진행 중으로 돌아가며, 그 기록은 다시 자동 완료하지 않습니다.
- UNI-PASS로 확인할 수 없는 건(번호 없음, FTA·환급·컨설팅)은 카드의 "통관완료"·"정산완료" 버튼으로 표시합니다.
- 기록에 요건승인번호나 정정 제출번호·차수·신청일자를 넣어 두면 요건 승인(API003)과 정정 처리상태(API052)도 카드에 표시합니다.

**추가 추적 (UNI-PASS)**: 기록 수정 창의 "UNI-PASS 추적 번호"에 번호를 넣어 두면 함께 확인합니다.
- 수입 건: 반입된 보세구역의 장치기간(API047)으로 **장치기간 만료일을 기한에 자동 등록**하고, 반출되면 처리 표시합니다. 제목·태그·원인에 '담보'가 있으면 담보해제 처리상태(API050)를 표시합니다.
- 수출 건: 적재지 검사 대상·완료 여부(API053)를 표시하고, 검사 대상이면 특이 표시를 제안합니다.
- 요건신청번호: 통관단일창구 처리상태(API025)를 표시하고, 결과가 통보되면 검역·요건 단계 체크를 제안합니다.
- 잔량 관리: "재수입조건부 수출"(수출신고번호+란번호+규격번호, API034) 또는 "재수출면세 수입"(수입신고번호+란번호, API042·045)을 고르면 잔량을 카드에 표시하고, 재수출 이행기한을 기한에 넣습니다. 잔량 관리 건은 잔량이 0이 될 때까지 자동 완료하지 않고, 0이 되면 완료 처리를 제안합니다.

## 업무 매뉴얼 (절차서 자동 갱신)

왼쪽 "업무 매뉴얼"에서 절차마다 실제 처리 통계(완료 건수, 평균 소요일, 통관완료까지 일수, 특이 비율, 실제로 받은 서류)와 특이 사례, 근거 법령, 최종 법령 검토일, 개정 이력을 봅니다. "인쇄"로 신입 교육용 A4 절차서를 뽑을 수 있습니다.
- 업무를 완료하면(직접 또는 자동 완료) 그 기록을 절차와 비교해 **개정 제안**을 올립니다: 절차에 없던 단계, 이번에 하지 않은 단계('필요 시'로 표시), 새 필요 서류, 아직 반영 안 된 특이 처리 내용.
- 관리자가 항목을 골라 "반영"하면 절차가 바뀌고 개정 이력(누가, 언제, 어느 케이스에서)이 남습니다. 추가 단계는 기록에서의 순서대로 끼워 넣습니다.
- 절차가 없는 업체×업무유형에 완료 기록이 2건 이상 있으면 "완료 기록으로 초안 만들기"로 절반 이상 기록에 나온 단계를 모아 초안을 만듭니다.
- 절차 수정 창에서 근거 법령(법·고시·조문)과 최종 검토일을 적습니다. 1년 넘게 검토하지 않았으면 빨간색으로 보입니다(시행 법령 자동 확인은 다음 단계).

**제안**: 자동으로 정하기 어려운 것은 "제안"으로 띄웁니다. 수리·필증 메일(요청·신청 메일 제외) → 통관완료로 표시, 정정·보완 메일 → 특이로 표시, 검역·검사 결과 메일 → 해당 단계 체크.

**홈 요약**: 홈 맨 위에 진행 중(통관 대기·정산 대기), 이번 주 완료(자동 완료 7일), 미연결 메일 대화(24시간 경과·새 의뢰), 7일 내 기한 네 칸과 시스템 상태(마지막 메일 수집·UNI-PASS 확인·Drive 자료 수집 시각)가 보입니다. 이미 받아 둔 데이터로만 계산하므로 추가 호출은 없습니다. 메일 수집이 2시간 넘게 멈추면 빨간 글씨로 알려 줍니다.

**메일 누락 방지**: "customs@ 메일" 화면의 **누락 경고 기준일** 이전에 끝난 대화는 '이전 대화'로 접어 두고 경고에서 뺍니다(처음 연결할 때 쌓인 과거 메일). 한 번에 정리하거나 기준일을 앞당겨 다시 볼 수 있습니다. 새 의뢰 후보는 회신(RE:)이 아닌 외부 첫 메일 중 제목에 요청·의뢰·신청·문의가 있거나 본문 첫머리에 '신고 요청', '통관 부탁' 같은 표현이 있을 때만 잡습니다. 기록과 연결되지 않은 customs@ 대화가 24시간을 넘으면 홈에 빨간 경고가 뜨고, 왼쪽 "customs@ 메일" 숫자가 빨간색이 됩니다. 업체가 보낸 첫 메일에 요청·의뢰·부탁·신청 같은 표현이 있으면 "새 의뢰 후보"로 맨 위에 올라오고 "업무 시작" 한 번으로 진행 중 기록이 만들어집니다.

**확인 필요**: 진행 중인데 3영업일 넘게 메일·자료·체크리스트·기록 수정이 없는 건을 홈과 "진행 중 업무" 맨 위에 모아 보여 줍니다.

**담당자와 절차 템플릿**: 기록에 담당자를 정할 수 있고(새 기록은 작성자), "진행 중 업무"에서 "내 담당만"으로 거를 수 있습니다. 절차에 기본 담당자와 챙길 기한 종류를 저장해 두면 "이 절차로 시작" 때 담당자가 들어가고 기한 칸이 그 종류로 맞춰집니다.

**customs@ 메일 대화 묶기**: 같은 대화(제목에서 RE:/FW:와 숫자 없는 [머리말]을 뺀 것)는 한 줄로 묶여 "3통 · 11-06~"처럼 보이고, 기록 만들기·붙이기·무시를 대화 단위로 합니다. 한 번 붙인 대화의 이후 회신은 같은 기록에 자동으로 붙습니다.

## 유사 업무 가이드·세관 질의 DB·품목 DB

**비슷한 과거 건**: 완료 기록 가운데 지금 건과 비슷한 것을 3~5건 골라 보여 줍니다. 같은 업체, 같은 업무 유형, 같은 품목(또는 HS 6단위·4단위), 제목·요약 키워드, 같은 선사(B/L 앞 4글자), 같은 정정 원인을 점수로 합칩니다. 업체만 같은 건은 빼고, 유형·품목·HS·키워드 중 하나는 겹쳐야 나옵니다.
- **진행 중 기록 카드**: "비슷한 과거 건 3건 · 평균 소요 4일 · 특이 1건 · 주로 ○○ 담당"이 접힌 상자로 붙습니다. 체크리스트가 비어 있는 새 건은 펼쳐진 채로 보입니다. 각 건의 절차, 실제 단계, 소요일(통관까지 일수), 담당자, 특이 처리 내용, 연결된 세관 질의가 보이고 "이 건의 단계·서류 가져오기"로 체크리스트에 없는 항목만 더합니다.
- **기록 창**: 제목·요약·B/L·품목을 고칠 때마다 아래 참고 패널이 다시 계산되고, 제목 아래에 요약 한 줄이 뜹니다. 진행 중인 같은 업체·유형 건도 보여 중복 등록을 막습니다.
- **customs@ 메일**: 대화마다 비슷한 과거 건 3개가 한 줄로 붙습니다. "업무 시작"을 누르면 메일 내용으로 업무 유형과 품목을 추정해 채웁니다(창에서 바꿀 수 있음).

**세관 질의 DB**: 왼쪽 "세관 질의 DB"에 세관에 묻거나 세관이 요구한 내용(질의일, 세관·부서, 분류, 업체, HS, 질의, 답변, 근거, 관련 기록)을 남깁니다. 진행 중 기록의 "질의 기록" 버튼으로 바로 남길 수 있고, 같은 HS·업체·키워드의 새 건을 진행할 때 가이드에 함께 뜹니다. 상단 검색에도 나옵니다. 업체를 지워도 질의는 남습니다.

**품목 DB**: 업체별 "품목·요건"을 HS 코드로 묶어 품목명, 업체, 세율·FTA, 수입요건(검역·식약처·화평법·화관법·KC·전파·위험물·폐기물 표시), 기록·세관 질의·KC 건수를 한 표로 봅니다. 같은 품목명인데 업체마다 HS 6단위가 다르면 "HS 확인 필요"로 맨 위에 보여 줍니다. HS 해설·관세율·세관장확인 요건의 UNI-PASS 자동 확인(API018·030·029·043·012)은 보류 중입니다.

## 정정 원인과 신고 전 점검표

기록 창의 "정정·보완 원인"에서 중량, 수량, 단가·금액, 품명·규격, HS 코드, 주소, 제조자, 거래구분, 원산지, 선적일, 증빙 보완 가운데 해당하는 것을 고릅니다. 예전 기록은 제목과 내용에 정정 관련 단어가 있으면 원인을 자동으로 추정해 보여 주고, 기록을 열어 저장하면 그대로 확정됩니다.

- **업체 화면의 "정정 주의"**: 그 업체에서 자주 나온 원인과 건수, 원인별 신고 전 점검 문구가 보입니다.
- **"정정 점검표 추가"**: 새 건을 시작할 때 기록 창 체크리스트에서 누르면 `[점검]` 항목이 맨 앞에 들어갑니다.
- **월간 리포트**: 그 달의 정정·보완 원인과 정정이 많은 업체가 표로 나옵니다.

왼쪽 "사유서 작성" 또는 업체 화면의 "사유서 작성" 버튼으로 엽니다.

| 종류 | 들어가는 내용 |
|---|---|
| C/O 선적 후 발급 사유서 | C/O 신청번호, 지연 사유 |
| C/O 정정발급 사유서 | C/O 발급번호, 정정 사유, 정정할 기재사항 |

1. 업체와 종류를 고르고 번호, 사유를 넣으면 문안이 자동으로 만들어집니다. 문안은 직접 고칠 수 있습니다.
2. "인쇄하기"를 누르면 A4 사유서가 새 창에서 열리고 인쇄 창이 뜹니다. PDF로 저장하려면 인쇄 대상에서 "PDF로 저장"을 고르세요.
3. "인쇄한 뒤 업무 기록으로 남기기"가 켜져 있으면 제출 기록 창이 이어서 열립니다. 수출신고 정정은 고른 정정 항목이 원인으로 함께 저장됩니다.

수신처와 대표자 이름은 업체별로 기억해 두었다가 다음에 자동으로 채웁니다. 증빙 보완 이력이 있는 업체(예: 레이)는 수출정정 첨부 서류에 ERP 캡처, S/N 목록, 서명 P/I가 미리 들어갑니다. 인쇄 창이 안 열리면 브라우저에서 이 사이트의 팝업을 허용하세요.

## customs@ 메일 수집 (한비로)

한비로 `customs@bsgc.co.kr`(가상 계정)로 들어온 메일을 업무 기록과 연결합니다. Gmail은 쓰지 않습니다.

**동작 방식**

1. customs@ 메일은 bsgc@, hwkim@, yjkim@ 메일함에 똑같이 들어옵니다. 사무실 상시 PC의 수집기가 **bsgc@ 메일함만** POP3로 15분마다 확인합니다.
2. 받는 사람·참조·배달 정보에 customs@가 있는 메일만 골라 제목, 보낸·받는 사람, 날짜, 본문 앞부분(600자), 첨부 파일명을 Apps Script로 보냅니다. **customs@가 아닌 bsgc@ 메일은 머리글만 보고 건너뛰며, 본문을 받지도 보내지도 않습니다.** 서버의 메일은 지우지 않습니다.
3. Apps Script는 Drive 유틸 폴더의 `BSGC 메일 색인` 시트에 쌓습니다.
4. Workspace에 로그인하면 최근 60일 메일을 받아, B/L·신고번호로 기록이 하나로 정해지는 메일은 그 기록에 자동으로 붙입니다. 나머지는 왼쪽 "customs@ 메일"에서 **기록 만들기 / 기록에 붙이기 / 무시**를 고릅니다. 붙인 메일은 기록 카드의 "customs@ 메일 n통"에서 보입니다.
5. 대표 메일함(bsgc@)으로만 받은 메일을 업무에 넣고 싶으면 customs@로 **손으로 전달**하세요. 수집기가 본문의 원래 보낸 사람을 읽어 업체를 찾습니다. bsgc@에 customs@로 **자동 전달 규칙은 만들지 마세요.** customs@가 다시 bsgc@로 배달해 메일이 돌 수 있습니다.
6. 직원이 고객에게 회신할 때 customs@를 참조에 넣으면 그 회신도 수집됩니다(보낸 메일은 따로 수집하지 않음).

**설치 (사무실 상시 PC, 한 번)**

1. 한비로 bsgc@ 계정 → 환경설정 → SMTP-POP3-IMAP → **앱 패스워드** 탭에서 수집기용 앱 패스워드를 만듭니다. "SMTP/POP3 사용"은 "사용", "원본 저장"은 "한비로메일에 원본 보관"인지 확인합니다.
2. python.org에서 Windows용 파이썬(3.9 이상)을 설치합니다. 설치 첫 화면에서 "Add python.exe to PATH"를 체크합니다.
3. `collector` 폴더를 그 PC의 원하는 위치(예: `C:\BSGC\collector`)에 복사합니다.
4. 그 폴더에서 명령 프롬프트를 열고 `python bsgc_mail_collector.py --setup`을 실행해 웹 앱 주소(`/exec`), Apps Script 토큰, 앱 패스워드, 수집 시작일을 넣습니다. 비밀값은 그 Windows 사용자만 풀 수 있게 암호화되어 `secret.bin`에 저장됩니다.
5. `python bsgc_mail_collector.py --test`로 시험합니다. 최근 20통에 대해 "수집/제외"가 표시되고, 아무것도 보내지 않습니다.
6. `install_task.bat`을 실행하면 15분마다 자동 실행됩니다. 기록은 같은 폴더의 `collector.log`에 남습니다.

**알아 둘 점**

- 수집 시작일은 처음에 최근 한 달로 시험하는 것을 권합니다(`--setup`의 기본값). 잘 되면 `python bsgc_mail_collector.py --start 2025-11-20`처럼 앞당기세요. 시작일 이전 메일은 '처리함'으로 기억하지 않으므로, 앞당기면 그 사이 customs@ 메일이 다음 실행부터 이어서 수집됩니다. 이미 수집한 메일은 다시 보내지 않습니다.
- 수집기는 최근 메일부터 거꾸로 확인하고, 시작일 이전 메일이 연달아 나오면 멈춥니다. 한 번에 최대 400통까지 확인하므로 기간을 크게 늘리면 몇 번(15분 간격)에 걸쳐 따라잡습니다.
- 한비로는 POP3 접속이 32일 동안 없으면 자동으로 끕니다. 수집기가 돌고 있으면 유지되지만, PC를 오래 끄면 한비로에서 다시 "사용"으로 바꾸세요.
- bsgc@ 웹메일에서 수집된 메일이 '읽음'으로 바뀌는지 첫날 확인해 주세요.
- Apps Script 토큰을 바꾸면(`resetToken`) 수집기에서도 `--setup`을 다시 실행하세요.
- 메일 색인 시트는 평문입니다. 공유하지 말고 대표 계정 Drive에만 두세요.

## 백업과 설정

- Drive가 `data.enc.json`의 이전 버전을 자동 보관하므로 그것이 1차 백업입니다.
- 비밀번호를 잊는 경우에 대비하려면 "데이터" 메뉴 → "평문 JSON 받기"로 받은 파일을 가끔 개인 폴더에 보관하세요. 평문이므로 공유 폴더나 GitHub에는 두지 마세요.
- 비밀번호를 바꾸면 새 파일을 받아 Drive에 저장해야 합니다. Drive의 이전 버전 파일은 예전 비밀번호로 열립니다.
- 업무 유형 목록은 "데이터" 메뉴에서 바꿉니다.
- `/` 키를 누르면 검색창으로 바로 이동합니다.
